# API 错误码表

> 所有接口返回**同一个信封**：`{"code": <业务码>, "message": <可读信息>, "data": <数据或 null>}`。
> `code` 与 HTTP 状态码**通常一致**，但以 `code` 为准 —— 前端只解析 `code`，不要依赖 HTTP。
> 每个响应都带 `X-Request-ID`，报障时提供它即可在日志里定位整条链路。

## 一览

| code | HTTP | 含义 | 典型触发场景 | 客户端应该做什么 |
|---|---|---|---|---|
| 200 | 200 | 成功 | — | 正常处理 |
| 400 | 400 | 请求参数不合法（业务层校验） | 用户名已存在、文件类型不支持、文件过大 | 提示用户修改输入，**不要重试** |
| 401 | 401 | 未认证 / 凭证无效 | 没带 token、token 过期、refresh 被轮换或吊销 | 用 refresh 换新 token → 仍失败则跳登录页 |
| 403 | 403 | 已认证但无权限 | 访问他人知识库、账号被禁用、非管理员访问管理接口 | 提示无权限，**不要重试** |
| 404 | 404 | 资源不存在 | 会话/知识库/文档不存在、路由写错 | 刷新列表或返回上一页 |
| 409 | 409 | 冲突 | 同一知识库上传内容相同的文件（sha256 重复） | 提示"已存在"，引导去列表查看 |
| 413 | 413 | 请求体过大 | 上传文件超过 `MAX_UPLOAD_SIZE_MB` | 提示大小限制 |
| 422 | 422 | 参数校验失败（框架层） | 缺字段、类型不对、长度越界 | 读 `data.errors` 定位字段 |
| 429 | 429 | 限流 / 登录锁定 | 超过每分钟配额；连续 5 次密码错误 | 按 `Retry-After` 等待；登录锁定需等 15 分钟 |
| 500 | 500 | 未预期异常 | 代码 bug、依赖异常未捕获 | 提示"服务异常"，可重试一次，仍失败请附 request_id 报障 |
| 502 | 502 | 上游（LLM/Embedding）失败 | 上游超时、429、5xx（已按配置重试并切换备用模型） | 可重试；持续失败说明上游不可用 |
| 503 | 503 | 依赖不可用 | 向量库未连接、检索失败、数据库不可用 | 提示"服务降级中"，**不要立刻重试**（会加剧拥塞） |

## 各 code 的具体 message

`message` 是给人看的，会随场景变化；下面这些是当前实现里实际会出现的（便于前端做文案映射或 E2E 断言）。

### 401

| message | 触发点 |
|---|---|
| `无效的访问令牌` | `get_current_user`：token 验签失败/类型不对 |
| `用户不存在` | token 合法但用户被删 |
| `用户名或密码错误` | 登录失败（用户不存在与密码错误**共用同一句**，防用户名枚举） |
| `无效的刷新令牌` | refresh 验签失败 |
| `刷新令牌已失效，请重新登录` | refresh 已被轮换/吊销（重放旧票） |
| `用户不存在或已被禁用` | 刷新时用户状态异常 |

### 403

| message | 触发点 |
|---|---|
| `账号已被禁用` | 登录或鉴权时 `is_active=false` |
| `无权访问该会话` / `无权访问该知识库` | 越权访问 |
| `需要管理员权限` | 管理接口 |

### 404

| message | 触发点 |
|---|---|
| `会话不存在` | 会话 id 不存在或不属于当前用户（不区分，避免探测） |
| `知识库不存在` | 同上 |
| `文档不存在` | 同上 |
| `Not Found` | 路由不存在（仍走统一信封，`code=404`） |

### 409 / 413

| message | 触发点 |
|---|---|
| `该文件内容已存在于本知识库（xxx.txt，状态 completed），无需重复上传` | sha256 内容去重 |
| `文件大小超过限制（xxx MB）` | 上传超限（流式写入时中途中断并删除半截文件） |

### 429

| message | 触发点 |
|---|---|
| `请求过于频繁，请稍后再试` | 用户/IP/全局每窗口配额用尽 |
| `登录失败次数过多，请 15 分钟后再试` | 同一用户名连续失败 5 次 |

### 502 / 503

| message | 触发点 |
|---|---|
| `LLM 调用失败：...` / `LLM 流式调用失败：...` / `LLM 工具调用失败：...` | 上游失败且重试/切换用尽 |
| `Embedding 服务不可用` / `向量生成失败：...` | 嵌入上游异常（上传时会导致文档 `failed`） |
| `知识库检索失败：向量检索出错` | pgvector 查询异常（`RetrievalError`，不静默降级） |
| `向量库未连接，当前无法处理文档` | PG 不可用时的上传前置检查 |

## SSE 接口的错误怎么给

流式接口（`POST /chat/.../stream`、`POST /agent/chat/stream`）在 200 响应**已经开始输出**之后，
无法再改 HTTP 状态码，因此约定：

```text
event: error
data: {"message": "知识库检索失败：向量检索出错", "code": 503}

event: done
data: {"iterations": 1, "tool_calls_count": 0, "model": "deepseek-chat"}
```

- **任何失败都必发 `event: error`，且紧跟 `event: done`**（否则前端会一直转圈）
- 已经生成的部分回答不会被丢弃：前端应保留并追加"（生成中断：原因）"
- 业务码与 HTTP 接口一致，客户端用同一套映射即可

## 与 `/docs` 的关系

- `GET /openapi.json` 是机器可读契约；`/docs`（Swagger UI）与 `/redoc` 是它的可视化
- 生产环境默认**关闭**（`DEBUG=false` 时），需要临时查看可设 `DOCS_ENABLED=true`
- 关闭后 `/docs` 与 `/openapi.json` 都返回 404，不泄露接口结构
