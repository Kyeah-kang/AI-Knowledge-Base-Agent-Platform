## 发现的缺陷（新增，P2）
现象：创建时间显示 `2026/10/23 12:30:17`，而当时本地时间约为 20:30（同日），相差 8 小时。
根因（代码证据，待 API 原文坐实）：
- backend/app/models/knowledge_base.py:36-43  created_at / updated_at 均 `default=utc_now`，注释写明"（UTC）"
- 前端 frontend/src/pages/KnowledgeBaseList.tsx:83  `new Date(t).toLocaleString("zh-CN")`
- 若后端序列化为不带时区标记的 `2026-10-23T12:30:17`，浏览器会按**本地时区**解析 => 把 UTC 值当本地时间显示
30 秒验证法：F12 → Network → 点 `knowledge-bases?page=1...` → Response → 看 created_at 是否带 `Z` 或 `+00:00`。
